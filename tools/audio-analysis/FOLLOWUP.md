# Повторная проверка аудиоанализа

## Записи и разметка

- Два рассказа одной участницы об одном сюжете, `Pic-RUS_01-f_Pr-R` и
  `Pic-RUS_01-f_Pr-T`. Это корпусные монологи. Подтверждённую открытую
  пару репетиций одного доклада найти не удалось.
- Для заминок использованы девять WAV/EAF: `Sib_01-f`–`Sib_07-f`,
  `NDS_034-m-z` и `Pic-RUS_01-f_Pr-R`. Второй рассказ той же участницы
  оставлен за пределами эксперимента с обучением. [Архивы и разметка ELAN](https://spokencorpora.ru/showelan.py)
- Для проверки записи из зала взята звуковая дорожка выступления Евгения
  Раевского на Вики-конференции 2021, 17:41, CC0. Прототип на модели
  small вернул 208 сегментов, 41 интервал от 700 мс и 110,1 слова в
  минуту. Замер обработки составил 1:57 при параллельной нагрузке.
  По ручной проверке транскрипта вступление занимает примерно первые
  19 секунд, около 17:23 начинается обмен репликами с модератором.
  Метрики всей записи включают обоих. Точность пауз в зале отдельно
  не оценивалась без эталонной разметки. [Запись конференции](https://commons.wikimedia.org/wiki/File:МГУ-учит-Википедии-_выступление-Евгения-Раевского-на-Вики-конференции-2021.webm)

В корпусной паре обе записи обработаны `large-v3-turbo-q5_0`.
Засчитывали эталонную паузу от 700 мс с абсолютной составляющей и
без заполнителя, если прогноз перекрывал больше половины интервала.

| Запись | Длительность | Слов/мин | Найдено размеченных пауз | Заполненные паузы по ELAN |
| --- | ---: | ---: | ---: | ---: |
| Pr-R | 1:15 | 128,1 | 7 из 9 | 3 |
| Pr-T | 1:10 | 127,4 | 7 из 8 | 0 |

Текстовый детектор пропустил все три заполненные паузы Pr-R.
В Pr-T он отметил усилительный повтор около 01:01, который есть и
в ELAN. В контексте это пример выразительности. Отметки обрывов и
самопоправок в ELAN использованы для просмотра примеров. Точность
детектора обрывов и голосовых акцентов в этом прогоне не измерялась.

## Звуковой эксперимент с заминками

`benchmark_hesitations.py` берёт окна по 400 мс с шагом 100 мс.
Из аудио извлекаются спектральные полосы, энергия и периодичность.
Линейная модель обучается на восьми записях и оценивается на
оставшейся, затем цикл повторяется для каждой записи. Разметка
`F(...)` в слое `Pauses` задаёт эталон. События сопоставляются
один к одному, с допуском 150 мс вокруг границ эталона.

На 16,1 минуты приходится 44 размеченных заполненных паузы.

| Порог | Совпадения | Точность | Полнота | Ложных отметок в минуту |
| ---: | ---: | ---: | ---: | ---: |
| 0,45 | 10 | 14,1% | 22,7% | 3,8 |
| 0,60 | 9 | 29,0% | 20,5% | 1,4 |
| 0,75 | 5 | 38,5% | 11,4% | 0,5 |
| 0,90 | 3 | 60,0% | 6,8% | 0,1 |

При пороге 0,60 модель пропускает 35 из 44 заминок. Это пилот на
малом наборе. Акустический счётчик оставлен экспериментом, в отчёт
фонового воркера по-прежнему попадают только текстовые кандидаты.

## Структура длинной речи

Для всех трёх режимов использован один транскрипт доклада Vallastro
длительностью 24:14. По ручной проверке текста подведение итогов
начинается около 23:22. Реплика с прощанием начинается около 24:09.
[Исходный доклад](https://commons.wikimedia.org/wiki/File:2026_Vallastro_presentation_on_writing_articles_on_scientific_themes_without_discussion.webm)

| Режим Qwen | Что получилось | Время разбора |
| --- | --- | ---: |
| Весь транскрипт | Ошибочный финал на 06:53–07:06 | 2:43 |
| Пятиминутные окна | 10 частей, финал пропущен | 2:20 |
| Окна и отдельная проверка последних двух минут | Прощание на 24:09–24:13, начало подведения итогов пропущено | 2:24 |

Время зависит от прогрева модели и нагрузки. По одному докладу можно
сравнить конкретные границы, качество метода в целом пока неизвестно.
В коде доступен последний вариант через `--structure-mode chunks`.
Он точнее локализовал прощание на этом примере. Покрытие основной части
и смысловые подписи всё ещё требуют проверки.

## Восстановление после перезапуска

Для стенда выбрана нативная macOS на MacBook Air M2. Spring, Postgres
и MinIO запущены в отдельном локальном окружении. Воркер поднят через
временный LaunchAgent с приватным файлом токена.

1. Через API загружено 90 секунд аудио. Дождались состояния `RUNNING`.
2. Воркер остановлен сигналом `SIGTERM`, Spring остановлен. В Postgres
   задача оставалась сохранена. Для ускорения теста срок её аренды
   выставлен в прошлое.
3. После старта Spring новый PID воркера, запущенный `launchd`, получил
   вторую аренду. Русский транскрипт из 15 сегментов сохранился с
   состоянием `SUCCEEDED`. Запись по старой аренде получила HTTP 409.

Временные сервисы остановлены. Для постоянного стенда используйте
постоянные пути к моделям и LaunchAgent из [инструкции](README.md).
